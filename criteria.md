# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
**before** any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe. *"The agent handles errors"* is an opinion.
*"When search returns nothing, the agent stops before calling the second tool,
in 5 of 5 tries"* is a criterion.

Under each one, write a sentence or two on **why that target** and not a
stricter one. A reason that says something about your tools, your loop, or the
data earns credit; *"80% seemed reasonable"* does not.

> Missing your own targets next unit costs you nothing. Setting a target so
> easy you can't miss it does.

**Two are written for you. You write three.**

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card — in at least 4 of 5 tries.

**Why this target:**
Search is deterministic for the same query, but the two model-backed tools can
fail when the provider is temporarily unavailable or return unusable text. Four
of five allows one transient model failure while still requiring the complete
workflow to work reliably.

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change — 5 of 5 tries.

**Why this target:**
This branch depends on a deterministic local search result, not generated model
text. If the result list is empty, the loop has the same clear condition every
time, so it should stop on every try.

---

## 3. The selected listing reaches outfit suggestions

Across five matching-query runs, `session["selected_item"]["id"]` matches the
`new_item["id"]` received by `suggest_outfit` in all 5 runs.



**Why this target:**
The session stores the selected result and passes that value directly to the
next tool. This is deterministic local control flow, so one failure would mean
the state handoff is broken rather than normal model variation.


---

## 4. The fit card includes the listing facts

Across five generated fit cards for matching queries, at least 4 captions
include the selected item's title, price, and platform at least once each.



**Why this target:**
The caption is generated by a model, so requiring every wording detail on every
run would be brittle. The title, price, and platform are the useful facts a
shopper needs, and four of five allows one imperfect generation to be measured
without hiding a recurring omission.


---

## 5. Search respects the price ceiling

Across five search queries with a maximum price, every returned listing costs
no more than that maximum in all 5 searches.



**Why this target:**
The ceiling is applied directly to numeric prices before ranking, so it is a
deterministic filter. Returning even one over-budget listing would violate the
user's explicit constraint.
